# 游戏可行性评估

> 评估对象：用户候选游戏清单（35 项，去重后）
> 硬件基线：STM32F407 @168MHz / 512KB Flash / 192KB RAM，240×240 圆屏（安全区为内接正方形 170×170，ORG=35），LVGL 8.3.11
> 输入：编码器（旋转+按键）、摇杆（模拟量+按键）、KEY1~KEY4、超声波 HC-SR04
> 输出：6×LED、蜂鸣器
> 框架：app_launcher（app_t 注册）+ game_common（生命值）+ sys_notify（声光）
> 美术约束：无图片素材，全部用几何图形 + 调色板表达

## 评估维度

1. **输入匹配**：编码器适合"光标/旋转/数值"，摇杆适合"方向/连续移动"，超声波适合"手势触发"
2. **屏幕适配**：网格类看格子能否放进 170×170；卷轴类看视野是否够用
3. **算力/内存**：F407 无压力于 2D 瓦片与简单物理；流体/刚体堆叠/复杂 AI 不行
4. **内容量**：几何风格能否表达玩法核心，是否需要大量剧情/素材
5. **框架契合**：能否直接挂 app_t，复用生命值/声光

## C 级：不建议

| 游戏 | 原因 |
|---|---|
| 小鳄鱼爱洗澡 | 流体物理（挖土引水）在 168MHz 上算不动，240px 也表现不出 |
| 老爹汉堡店 | 经营类 UI 密集，多工位在 240 圆屏摆不下 |
| 赵云与阿斗 | RPG 内容量（剧情/精灵/关卡）远超几何风格能承载 |
| 打屁股 | 机制与打地鼠完全相同，作为其皮肤合并即可 |

## 结论与建议

### 最推荐（差异化 + 工作量小）

1. **小恐龙跳跃（超声波跳）**——输入创意，评委/同学一眼记住
2. **打地鼠（超声波锤）**——同上，互动性最强
3. **俄罗斯方块**——经典完成度高，必做
4. **坦克射击**——摇杆+按键组合最爽快的动作游戏
5. **电脑鼠**——算法可视化，与课程项目气质最搭

### 开发顺序建议

1. 先做 **2048 / 数字华容道 / 扫雷**（纯网格逻辑，各约半天，快速扩充游戏列表）
2. 再做 **小恐龙 / 打地鼠**（超声波交互，需把 HC-SR04 采样从 250ms 提到 60~100ms——游戏内直接调驱动，不走 sys_sensor 节流）
3. 然后 **俄罗斯方块 / 大鱼吃小鱼**（中等工作量）
4. 最后挑 **坦克射击 / 飞行射击**（动作类收尾）

### 通用约定（新游戏直接沿用）

- 输入映射：编码器=光标/旋转/数值，摇杆=方向/移动，ENC 键+JS 键=确认，KEY1=返回，KEY2/KEY3=功能键
- 生命值/提示音：复用 `game_common` + `sys_notify`，不要在游戏里直接驱动 LED/蜂鸣器
- 布局：优先使用内接正方形 ORG=35、170×170；需要满屏的游戏注意圆角裁剪，关键信息别放四角
- 中文显示：菜单名与提示语走中文字模方案（见另一文档），游戏内部画面以图形为主、文字最少化
